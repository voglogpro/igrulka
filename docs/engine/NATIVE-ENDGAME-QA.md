# Нативная проверка победы и сноса руин

Сценарий проверяет исходный инспектор разрушенного собственного здания, снос руин, последний оплаченный ракетный удар, экран победы, сохранение завершённой кампании, продолжение и создание новой кампании. Исходная симуляция, экономика, HP, время производства и правила не изменяются.

Подготовка из корня репозитория:

```powershell
node scripts/native-parity-paid-advanced-fixture.mjs --run
node scripts/native-parity-paid-endgame-fixture.mjs --run
node scripts/prepare-native-paid-endgame-qa.mjs
```

Первые два скрипта без `--run` выводят план и не запускают симуляцию. Результаты сохраняются в игнорируемую папку `artifacts/native`. Endgame использует проверенный `paid-advanced-complete.json`, затем создаёт `paid-endgame-prefinish.json`, `paid-endgame-complete.json` и `paid-endgame-report.json` с расходами, командами, реальными попаданиями и SHA-256 сохранений.

Чтобы получить собственные руины, сценарий оплачивает изолированный МОГ, дожидается строительства и уничтожает его настоящей произведённой, доставленной и запущенной крылатой ракетой. Это явно обозначенная проверочная миссия с дружественным огнём, разрешённым исходным наведением на точку. Затем четыре оплаченных попадания снижают здоровье вражеского штаба с 1100 до 44; ещё одна оплаченная ракета уже доставлена на корабль. Результат назначается только исходной симуляцией при последнем попадании.

Нативный запуск требует полного проверяемого Windows-пакета:

```powershell
$qaFile = (Resolve-Path artifacts/native/parity-paid-endgame-qa.js).Path
$captureFile = Join-Path (Get-Location) artifacts/native/paid-endgame-viewport.png
& 'C:/path/to/Windows-package/Skyfront.exe' -- --qa-parity "--qa-script=$qaFile" "--capture=$captureFile"
```

QA использует отдельный профиль, исходный импорт через `File`/`DataTransfer`, настоящие перезагрузки страницы, DOM-кнопки и обработчик наведения. Проверяются ресурсы, запас корабля, координаты пуска, реальное разрушение, удаление модели руин, исходный экран победы и резервная копия завершённой кампании после создания новой. Сцена Godot сверяется с исходной сценой через ACK. Итоговая запись `SKYFRONT_PARITY_WEB_QA` должна содержать `stage:"complete", passed:true`; успешного кода выхода или одного изображения недостаточно.

У исходного экрана победы нет кнопки продолжения. Проверяется настоящая кнопка «Продолжить» в стартовом меню после сохранения и повторного открытия, затем настоящая «Новая кампания» на экране победы.

Это локальная интеграционная проверка в исходном режиме `multiplayer` с бездействующим вторым человеком; реального сетевого подключения здесь нет. Последний полёт выполняется исходным `E.step` при паузе. Сценарий не доказывает конкурентный баланс, FPS боя, внешнюю интернет-сеть, физический ввод Windows или качество прослушивания. Синтетическая галерея моделей и прямые изменения ресурсов/HP/результата не используются.

Полная матрица приёмки находится в [PARITY-816.md](PARITY-816.md).
