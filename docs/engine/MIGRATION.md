# Перенос «Небесного рубежа» на игровой движок

Подготовка от 1 ноября 2026. Пользователь подтвердил основную платформу:
**самостоятельная игра для Windows x64 (.exe)**. База исследования — последняя
8.16.0, `68580f070954c59ffb0095e8e51a3c559802cd45`, включая флот и промышленность.
Рабочая ветка подготовки — `codex/engine-migration-prep`. Полный перенос ещё
не выполнен; здесь зафиксированы выбор, порядок работ и условия приёмки.

## Решение

Выбираем **Godot 4.7.2 .NET + C#** для первого нативного прототипа. Это
проверяемый выбор под имеющийся ноутбук, а не обещание конкретного FPS.
Основной вариант изображения сначала проверяем в Compatibility; Mobile
сравниваем на той же сцене. Forward+ оставляем для более мощного оборудования.
Версию 4.8 beta не берём за основу производства.

Godot можно запустить переносимым инструментом, вести текстовые сцены и C#
в Git, собирать Windows и headless-процессы. Движок распространяется под MIT;
его уведомления и лицензии зависимостей включаем в поставку. C#-игра Godot 4
по текущей документации не экспортируется в браузер. Подтверждённая Windows
платформа позволяет принять это ограничение; браузерный проект остаётся
самостоятельной прежней версией.

Источники: [официальная загрузка](https://godotengine.org/download/windows/),
[лицензия](https://godotengine.org/license/),
[C# и SDK](https://docs.godotengine.org/en/stable/tutorials/scripting/c_sharp/c_sharp_basics.html).

| Движок              | Что полезно стратегии                                                              | Что влияет на наш выбор                                                                                                             |
| ------------------- | ---------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Godot 4.7.2 .NET    | C#, сцены, PBR, пакетная графика, инструменты профилирования, переносимый редактор | Подходит для доступной среды; для крупных армий нужны собственная организация данных, LOD и ограниченные эффекты                    |
| Unity 6.3 LTS / URP | Развитые средства 3D, Terrain, анимации, Jobs/Burst и возможный ECS                | Сильная альтернатива, но установка и рабочий процесс тяжелее; переход на ECS тоже требует проектирования, не автоматический перенос |
| Unreal Engine       | Развитые средства освещения, материалов, эффектов и анимации                       | Рекомендации редактора 32 ГБ RAM / 8 ГБ видеопамяти плохо соответствуют этому ноутбуку; не выбираем первым                          |

Сравнение — инженерная оценка, не общий рейтинг. Если одинаковый прототип
Godot не проходит приёмку после профилирования, пересматриваем выбор до
полного переноса правил. Не устанавливаем три больших движка одновременно.

[Unity LTS](https://unity.com/releases/unity-6/support),
[Unity требования](https://docs.unity3d.com/6000.3/Documentation/Manual/system-requirements.html),
[Unreal требования](https://dev.epicgames.com/documentation/unreal-engine/hardware-and-software-specifications-for-unreal-engine).

## Что реально есть сейчас

- Ryzen 5 3500U: 4 ядра / 8 потоков; Radeon Vega 8; Windows сообщает около
  5,9 ГиБ доступной установленной памяти. При подготовке свободно около
  10,6 ГиБ на C: и 0,5 ГиБ на D:. Это сведения CIM, не измерение скорости.
- Имеющаяся игра использует настоящий 3D-рендерер Three.js. Простота вида
  связана также с геометрией, материалами, светом и анимацией, а не только
  с браузером. Новый движок не создаёт качественные ассеты автоматически.
- В `src/game/` примерно 20 тысяч физических строк независимых JS-правил.
  Их нельзя просто импортировать как C#. Подробности — [SYSTEMS](SYSTEMS.md).
- Blender 4.5.14 LTS уже доступен в локальных инструментах предыдущей рабочей
  копии. Исходник танка/РСЗО экспортирует JS-массивы вершин, не GLB. Большая
  часть домов, пехоты, кораблей и эффектов тоже задаётся кодом Three.js.
- Сетевой формат 18 и сохранения 23 — реальные контракты 8.16. Некоторые
  заголовки прежних README/документов ещё относятся к 8.15 и более ранним.

## Архитектура новой игры

```text
native/
  Skyfront.Core/          правила, данные, экономика, бой, RNG; без Godot
  Skyfront.Persistence/   версии файлов, импорт прежнего JSON, миграции
  Skyfront.Protocol/      команды, события, представления сторон, снимки
  Skyfront.Client/        проект Godot, камера, сцены, звук, интерфейс
  Skyfront.Server/        будущий headless-хост тех же правил
  Skyfront.Tests/         сценарии, сравнение с JS-эталоном, сохранения
art-source/              Blender-исходники и исходные текстуры
assets/native/           подготовленные GLB, материалы, анимации, аудио
```

Это целевая структура, не уже созданный порт. Не создаём пустую сцену на
каждого солдата с отдельным AI, физикой, материалом и `_Process`. Правила
хранят массивы данных, пространственные индексы и очередь задач. Отрисовка
получает только нужное ей представление и интерполирует между тиками.

На первом графическом прототипе допустим адаптер к существующей Node/JS
симуляции: так одновременно проверяем новый вид и сохраняем механику.
Такой мост — временный инструмент разработки. Полноценная одиночная поставка
должна запускаться без установленного Node, браузера и внешнего сервера;
целевой вариант — локальные C#-правила. Не называем мост завершённым переносом.

Для сети сначала сохраняем существующий авторитетный Node-сервер и пишем
совместимый адаптер Godot `WebSocketPeer`: handshake, команды, sequence/ACK,
delta-v1, восстановление места, приватность. Godot RPC/ENet не совместимы с
нашим прикладным протоколом сами по себе. Замена транспорта и серверной
архитектуры — отдельный последующий этап.

[WebSocket](https://docs.godotengine.org/en/stable/tutorials/networking/websocket.html),
[headless](https://docs.godotengine.org/en/stable/tutorials/export/exporting_for_dedicated_servers.html).

## Каким делаем изображение

Направление — читаемая военная стратегия: тёмно-зелёная техника, естественная
земля, вечерний свет, хорошо различимые силуэты, огонь и дым. Близкая камера
показывает детали; общая карта сохраняет ясность и скорость.

1. **Ландшафт и море.** Рельеф секторами, несколько материалов земли, нормали,
   прибрежное мелководье и видимое дно у берега. Шейдер волн, блики и следы
   кораблей. Первый вариант воды обходится без дорогих отражений всего мира.
2. **Освещение.** Один управляемый солнечный источник и согласованное небо;
   тени с ограниченной дальностью и разрешением. Смена суток не прыгает вслед
   за камерой. Цветокоррекция поддерживает детали в тенях, а не прячет карту.
3. **Техника.** GLB с отдельными корпусом, башней, стволом и колёсами; нормали,
   небольшие текстуры, 2–3 уровня детализации. Не наращиваем геометрию там,
   где детали не видны с обычного масштаба. Силуэт важнее мелких болтов.
4. **Пехота.** Скелет, движение, остановка, прицеливание, стрельба, перезарядка,
   укрытие и гибель. Вдали — упрощённая геометрия и более редкое обновление
   анимации; партии по роли и сектору. MultiMesh не обеспечивает независимую
   Skeleton3D-анимацию каждого экземпляра. Проверяем обычные skinned-модели
   вблизи и отдельный упрощённый/VAT-шейдерный вариант вдали.
5. **Бой.** Пулы трассеров, вспышек, осколков, дыма и кратеров. Длинный след
   тяжёлого попадания, меньший — лёгкого. Графика читает попадания симуляции;
   физика красивых обломков не меняет урон и захват. Нет отдельного света на
   каждую пулю и бесконечных частиц.
6. **Погода.** Умеренный дождь рядом с камерой, влажные поверхности, ограниченная
   дымка над землёй. Объекты согласованы по глубине. Без тумана войны, полос
   экрана и постоянно закрытого туманом неба. Зерно — очень слабое.
7. **Интерфейс.** Масштабируемые Godot Control/Container, компактные карточки,
   важное действие всегда видно. Производство, оборона и атака доступны без
   повторного создания всей армии/карты из нажатия кнопки.

Дорогие экранные эффекты, объёмный туман и отражения не входят в обязательную
базу Vega 8. Режим высокого качества расширяет ту же художественную систему
на более мощном GPU; не меняет механику и дальность видимости противника.

## Ассеты и звук

Основной обмен Blender → Godot — glTF 2.0 / GLB. Первыми подготавливаем один
танк, МОГ, стрелка, один жилой дом, завод и корабль. Сохраняем раздельные
шарниры, точки выстрела и занимаемое игровое место. Модельные величины старой
игры не считаем автоматически реальными метрами.

Покупка наборов пока не нужна. Кандидаты для исходных текстур/HDRI —
[Poly Haven](https://polyhaven.com/license), для отдельных вспомогательных
ассетов — [Kenney](https://kenney.nl/support). Их страницы описывают CC0;
для каждого действительно импортированного файла сохраняем источник,
версию, автора, лицензию и изменения. На этапе подготовки эти наборы не
скачаны, совместимость стиля не считается проверенной.

Одобренные пользователем записи и характер звука сохраняем. WAV переносим
из исходников; дождь в Opus конвертируем офлайн в поддерживаемый формат,
сверяя длительность, петлю и громкость. Движок штатно импортирует WAV,
Ogg Vorbis и MP3. Не декодируем и не создаём тяжёлые звуковые ресурсы во время
попадания. Позиционный звук, бас/эхо, лимит голосов, mute и пауза проходят
отдельное сравнение; новые синтетические звуки не добавляем.

[Импорт 3D](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_3d_scenes/available_formats.html),
[импорт аудио](https://docs.godotengine.org/en/stable/tutorials/assets_pipeline/importing_audio_samples.html).

## Последовательность работ и условия перехода

| Этап                     | Результат                                                            | Когда этап завершён                                                                 |
| ------------------------ | -------------------------------------------------------------------- | ----------------------------------------------------------------------------------- |
| 0. Подготовка            | Аудит 8.16, выбор движка, рабочая цепочка C#, план                   | Компиляция и запуск диагностического проекта; ограничения записаны                  |
| 1. Графический фрагмент  | Камера RTS, берег/море, улица, 10 домов, танк, пехота, МОГ, один бой | Windows-сборка; сравнимые кадры и замеры на Vega 8; управление удобно               |
| 2. Масштаб               | Та же сцена с массовыми силами и эффектами                           | Пройдена [матрица измерений](VALIDATION.md), найденные пики разобраны               |
| 3. Правила               | C#-ядро по подсистемам с JS-эталоном                                 | Проверены реальные цены, RNG, маршруты, боезапас и все режимы, а не только картинка |
| 4. Полная одиночная игра | UI, экономика, производство, фронт, авиация, ПВО, флот, сохранения   | Все механики 8.16 учтены, Windows запускается офлайн без внешних зависимостей       |
| 5. Кооператив            | Два самостоятельных города людей и два бота                          | Два настоящих клиента, приватность и обрывы связи; длительный бой                   |
| 6. Поставка              | Готовый пакет, настройки, лицензии, обновление                       | Повторяемая release-сборка и проверка на чистой Windows                             |

Срок полного переноса не объявляем до этапов 1–2: объём правил уже значителен,
а главные риски — массовые юниты и качество ассетов. Смена движка не заменяет
исправление алгоритмов навигации, перерасчётов дорог и выделения памяти.

## Подготовленные инструменты и точные границы проверки

Инструкции, версии, контрольные суммы и результат диагностики —
[TOOLCHAIN](TOOLCHAIN.md). Проверочный проект в `tools/engine-probe/` не является
первым игровым прототипом: он проверяет C# и связи с API Godot без GPU-замера.
Массовая сцена, новые модели, хорошее море и готовый EXE игры — следующие работы.
