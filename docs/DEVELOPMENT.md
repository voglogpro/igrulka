# Разработка

## Установка и запуск

Для разработки нужен Node.js 24+.

Изменения 8.6 ведутся в отдельном worktree `igrulka-development`, ветка `codex/frontline-command`. Стабильную копию `igrulka/main`, где идёт пользовательская партия, не пересобирайте и не перезапускайте. Автономный HTML и проверки также запускайте из рабочей ветки разработки.

Из корня рабочей копии:

```sh
npm ci
npm start
```

Для запуска сервера без открытия вкладки: `npm start -- --no-open`. Можно задать порт: `npm start -- --no-open --port=8790`. Сервер слушает только `127.0.0.1`; при занятом стандартном порте выберет следующий и напечатает адрес.

Для готовой автономной версии Node.js не нужен: откройте `play/Skyfront.html`. После изменения исходников обновите этот файл командой `npm run build`.

Для интернет-партии хозяин открывает `Играть через интернет.cmd`. Скрипт подготавливает npm-зависимости при первом запуске. Сначала `server/ssh-tunnel.mjs` использует системный OpenSSH и localhost.run с отдельным файлом известных хостов; личные ключи и аккаунт не нужны. Если SSH недоступен, резервный `server/tunnel.mjs` загружает фиксированную официальную версию `cloudflared`, проверяет SHA-256 и кэширует бинарный файл в игнорируемой `.tools/cloudflared/`. После установки зависимостей тот же запуск доступен как `npm run multiplayer:internet` или `node server/index.mjs --internet --no-open`. Сервер слушает loopback, наружу после проверки доступности выдаётся временный HTTPS/WSS-адрес. Другу нужны только браузер и приглашение. Процесс должен оставаться запущенным; роутер настраивать не нужно. Бесплатный домен localhost.run временный и ограничен по скорости. Ограничения и порядок подключения — [MULTIPLAYER.md](MULTIPLAYER.md).

Оркестрация транспорта находится в `server/internet.mjs`, исходящий прокси — в `server/proxy.mjs` (точная зависимость `https-proxy-agent@9.1.0`). Учитываются переменные прокси и настройки Windows, включая исключения; глобальные настройки не меняются. Готовность публичного адреса требует JSON сервера и полного ответа 32 КБ, три успешные проверки. Проверка только HTTP-статуса недостаточна: ограниченный сетевой маршрут может оборвать тело после заголовков.

У хозяина запускается локальная вкладка с `?multiplayer=1`, а `/api/server-info` предоставляет публичный адрес приглашения. Интернет-HTML не встраивает шрифты, использует внешние файлы с `font-display: swap`, кешированный gzip и экран загрузки до готовности приложения. Автономная сборка продолжает встраивать все шрифты. Интернет-WSS согласует стандартное `perMessageDeflate` с `level: 1`, `memLevel: 7`, `concurrencyLimit: 2`; LAN по умолчанию без сжатия, протокол остаётся 6.

## Порядок работы

SSH использует существующий HTTP(S)-прокси условно через `server/ssh-proxy.mjs` и OpenSSH `ProxyCommand`; без подходящего прокси остаётся прямое соединение. Мост ограничен `localhost.run:22`, не передаёт настройки прокси в аргументах процесса и не выводит их в диагностику. Прокси может запрещать CONNECT к этому порту.

В `src/network/client.js` контролируется отсутствие входящих сообщений 15 секунд. При активном цикле событий проверка примерно через 15–18 секунд запускает переподключение; терминальная ошибка возврата очищает сохранённые данные комнаты. Это покрывает потерянное сообщение `closed`, но не гарантирует точный срок в замороженной браузером вкладке.

1. Найдите систему в [CODE_MAP.md](CODE_MAP.md). Параметры и внешний вид меняются в разных файлах.
2. Внесите изменение в `src/`. Не редактируйте сгенерированный HTML и сторонний код.
3. Выполните `npm run format`, затем `npm run check`.
4. Если затронуты графика, интерфейс или управление, проверьте соответствующий браузерный сценарий. При изменении экономики или ИИ выполните длинные кампании.
5. Проверьте `git diff`, добавьте исходники и обновлённый `play/Skyfront.html` в один коммит.

## Проверки

| Команда                             | Что проверяет                                                                                              |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| `npm test`                          | Текущие игровые механики, графические зависимости и два набора регрессий старого прототипа                 |
| `npm run lint`                      | Необъявленные переменные и ошибки JavaScript                                                               |
| `npm run format:check`              | Единое оформление исходников и документации                                                                |
| `npm run build`                     | Сборку кода, шрифтов и лицензий в один HTML                                                                |
| `npm run check`                     | Все четыре проверки выше                                                                                   |
| `npm run test:soak`                 | 12 кампаний по 20 игровых минут с контролем чисел и работы бота                                            |
| `node tests/soak/city-services.mjs` | Четыре кампании по 10 минут: дорожные бригады обеих сторон, точная оплата, разрывы, отключения и save/load |
| `node tests/soak/frontline.mjs`     | Строительство укреплений, ограниченный резерв, возврат на пост и продолжение после save/load               |
| `npm run test:browser`              | Все сценарии Chrome/Playwright, включая офлайн-запуск и исходные модули по HTTP                            |

Браузерные тесты требуют Python 3.11+:

```sh
python -m pip install -r tests/browser/requirements.txt
python -m playwright install chromium
```

На Windows используется установленный Chrome из стандартной папки, если он найден. В остальных случаях используется Chromium Playwright. Свой браузер можно указать переменной `CHROME_PATH`.

Отдельные сценарии:

```sh
python tests/browser/smoke.py
python tests/browser/camera.py
python tests/browser/infantry.py
python tests/browser/army_controls.py
python tests/browser/deployment.py
python tests/browser/combat.py
python tests/browser/migrations.py
python tests/browser/lighting.py
python tests/browser/audio.py
python tests/browser/atmosphere.py
python tests/browser/grain.py
python tests/browser/frontline.py
python tests/browser/territory_routes.py
python tests/browser/production.py
python tests/browser/multiplayer.py
python tests/browser/run.py army_controls multiplayer
```

Сначала выполните `npm run build`: сценарии проверяют `play/Skyfront.html`. `smoke.py` также сам запускает сервер и проверяет исходные ES-модули. Проверка света может сравнить старую ошибку с текущей сборкой, если вручную положить прежний HTML в `artifacts/qa/baseline-before-lighting8.html`; без него проверяется текущая версия.

Результаты, снимки и тестовые сохранения попадают в `artifacts/qa/`, которая исключена из Git. Сценарии запускаются с отдельным профилем браузера. Счётчики ресурсов проверяют выделение геометрий и материалов, а не обещают конкретный FPS на любом компьютере.

Профильные проверки погоды, звука и новых городских служб:

```sh
node --test tests/unit/weather.test.mjs tests/unit/weather-rendering.test.mjs tests/unit/audio-atmosphere.test.mjs
node --test tests/unit/city-services.test.mjs tests/unit/service-rendering.test.mjs tests/unit/network-services.test.mjs
node tests/soak/city-services.mjs
node --test tests/unit/defense-fortifications.test.mjs tests/unit/frontline-command.test.mjs tests/unit/defense-rendering.test.mjs
node --test tests/unit/ui-session-refactor.test.mjs tests/unit/ui-input-refactor.test.mjs tests/unit/ui-strike-refactor.test.mjs tests/unit/ui-command-catalog.test.mjs
node --test tests/unit/network-invite.test.mjs tests/unit/network-defense.test.mjs tests/unit/internet-tunnel.test.mjs
node tests/soak/frontline.mjs
```

Модульные сценарии проверяют правила и графические данные без 3D-браузера. `tests/browser/atmosphere.py` запускает исходные модули через HTTP и проверяет дождь, туман, ремонтную станцию и её машины, сохранение и паузу. Автономный файл проверяют остальные 3D-сценарии и офлайн-часть `smoke.py`. Звук отдельно проверяется `tests/browser/audio.py`. При совместной работе запускайте тяжёлые браузерные сценарии последовательно, чтобы несколько программных WebGL-миров не искажали измерения.

Для уже работающего интернет-сервера используйте локальный адрес хозяина, который сообщил запуск; сценарий получает публичный адрес гостя из метаданных сервера:

```sh
python tests/browser/multiplayer.py --url=http://127.0.0.1:ПОРТ
```

## Сохранения

Версия приложения и версия состояния различаются: приложение 8.7.0, состояние 13. При перемещении файлов версию состояния не повышаем. Новые поля состояния требуют совместимых значений по умолчанию, миграции и проверки через `save → load`. Районы старого формата добавляются нейтральными; старые очереди без `destination` сохраняют обычную точку сбора. `destination: null` означает ждать у базы. Кампании версий 3–10 получают пустой `serviceVehicles`, сохраняя город, армию, ресурсы и погоду; с формата 11 коллекция ремонтных машин и её поля проверяются явно. Формат 12 добавляет память фронта и проверку добровольного резерва, заданий помощи и прогресса укреплений в `game/defense/persistence.js`; старые кампании не превращают существующие гарнизоны в автоматический резерв. Метаданные пополнений и начала траектории снарядов, включая optional `originY`, `gravity` и `arc`, проверяются при импорте. С формата 13 у сторон есть `oil`, у сгоревших хранилищ — `fire`, у состояния — коллекция кораблей `ships`; кампании 3–12 получают стартовую нефть и пустой флот (`persistence/oil.js`). Правило `rules.oil = false` отключает требования нефти в сценариях, которые проверяют одну механику.

Сетевой протокол — 6. Он сохраняет дуэль, кооператив, ремонтную службу и баллистическую интерполяцию, добавляя `auto-defense` и разрешённое представление фронта. Чужие планы, задания и разведывательная память не публикуются. Сетевые снимки не сохраняются как одиночная кампания; место восстанавливается отдельным ключом комнаты. Этот ключ не добавляется в URL-приглашение. Серверные команды и возврат проверяются также в `tests/unit/network-*.test.mjs`.

Старая игра на рабочем столе, автономный файл из другой папки и локальный сервер могут иметь разные области браузерного хранения. Для переноса кампании используйте в игре «Настройки → Экспорт кампании», затем «Импорт кампании». Не копируйте профиль браузера и не очищайте его ради тестов.

## История и готовая сборка

В `docs/history/` лежат планы версий 4–8. `archive/legacy/` содержит старые движок и мир только ради тестов; приложение их не импортирует. Разовые скрипты, которыми прежде переписывалась игра, не нужны для запуска или дальнейшей разработки.

GitHub Actions выполняет форматирование, анализ, тесты и сборку. Он также проверяет, что заново собранный `play/Skyfront.html` совпадает с файлом в коммите. CI не запускает тяжёлые браузерные сценарии; их выполняем локально по характеру изменений.
