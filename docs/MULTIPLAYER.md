# Сетевая дуэль · LAN preview

Два игрока строят города с нуля на общей карте. Стартовые ресурсы и доходы равны, бота нет. Сервер рассчитывает экономику, строительство, движение, попадания и победу; игроки отправляют команды. Одиночная кампания в браузере сохраняется отдельно и возвращается после выхода из сетевой сессии.

## Запуск на одном компьютере

1. Для сервера нужен Node.js 24 или новее. Откройте `Сетевой сервер.cmd`; при первом запуске он установит зависимости из lock-файла. Через терминал можно выполнить `npm ci`, затем `npm run multiplayer`.
2. Оставьте окно сервера открытым. По умолчанию адрес — `http://127.0.0.1:8788`.
3. Откройте этот адрес в двух браузерах или независимых профилях. На начальном экране нажмите «Сетевая дуэль».
4. Первый игрок создаёт комнату, второй вводит её шестизначный код. Оба нажимают «Я готов», создатель — «Начать матч».
5. Во время матча меню комнаты доступно через настройки. «Завершить сессию» закрывает комнату обоим игрокам и возвращает их одиночные кампании.

Клиентом может служить и автономный `play/Skyfront.html`: укажите в его сетевом меню адрес работающего сервера. Сервер и клиент должны быть из одной версии проекта.

## Второй компьютер в локальной сети

Запустите сервер с разрешением слушать сетевые интерфейсы:

```sh
npm run multiplayer -- --host=0.0.0.0
```

На другом компьютере откройте `http://IP-КОМПЬЮТЕРА-СЕРВЕРА:8788`. Устройства должны находиться в одной доступной локальной сети; если Windows запросит доступ для Node.js, разрешите его для используемой частной сети. Не требуется менять правила брандмауэра заранее.

Сервер по умолчанию слушает только этот компьютер. Этот вариант предназначен для доверенной локальной сети. Публичный интернет-сервис, Steam Networking и автоматический поиск игроков здесь ещё не реализованы.

## Обрыв связи и возврат

При потере соединения одного игрока сервер останавливает симуляцию всей комнаты. Клиент пробует восстановить подключение и своё место; накопленные ресурсы и приказы остаются на сервере. После перезагрузки страницы откройте сетевое меню и нажмите «Вернуться в прошлую комнату». Для этого в `sessionStorage` текущей вкладки хранится случайный ключ места; он не попадает в одиночное сохранение или общие снимки матча.

Матч продолжается при скрытии вкладки, пока оба подключения живы. Кнопка одиночной паузы в сетевом матче отключена. После отключения обоих игроков комната хранится ещё 15 минут. Остановка процесса сервера удаляет комнаты: постоянное сохранение сетевых партий пока отсутствует.

## Где находится код

| Часть                                                       | Файл                                       |
| ----------------------------------------------------------- | ------------------------------------------ |
| Запуск и адрес сервера                                      | `server/index.mjs`                         |
| Комнаты, места, готовность, тик и восстановление            | `server/rooms.mjs`                         |
| Разрешённые команды и проверка принадлежности               | `src/network/commands.js`                  |
| Данные, доступные конкретному игроку, и перестановка сторон | `src/network/perspective.js`               |
| WebSocket-клиент, ответы на команды и интерполяция          | `src/network/client.js`                    |
| Меню комнаты                                                | `src/ui/multiplayer.js`, `multiplayer.css` |
| Передача игровых действий из интерфейса                     | `src/ui/app.js`, функция `execute`         |

Симуляция работает с шагом 50 мс, снимки отправляются каждые 100 мс. Клиент сглаживает движение между последними снимками, не рассчитывая исход боя самостоятельно. Идентификаторы и координаты объектов общие; для интерфейса собственная сторона всегда имеет номер 0.

Сервер принимает только разрешённые команды с проверенными аргументами. Сторону определяет закреплённое место соединения. Поддельные ресурсы, импорт состояния, чужие приказы, повторные номера команд, неизвестные виды вооружения и некорректные координаты не принимаются. Номер подтверждённой команды сохраняется при восстановлении места. Размер входящего сообщения ограничен 16 КиБ, частота — 40 сообщений в секунду; медленное соединение закрывается вместо бесконечного накопления снимков.

В 8.3 используется протокол 3. Команда `deploy` оплачивает партию с индивидуальным местом назначения, а приказы полного отряда переназначают его ещё готовящееся пополнение. `district`, `district-repair`, `route-add`, `deliver`, `factory-plan` также проходят через шлюз принадлежности и аргументов. Районы общие, а планы заводов, будущие пути и состав очередей войск доступны лишь своему игроку. Клиент с явно указанным старым протоколом не создаёт комнату и не входит в неё. Обновляйте сервер и оба клиента вместе.

Скрытые солдаты и точные приказы противника не передаются чужому клиенту. Карта и городские объекты открыты по правилам игры; маскировка пехоты сохраняется.

## Проверки

```sh
node --test tests/unit/network-commands.test.mjs tests/unit/network-server.test.mjs tests/unit/network-client.test.mjs
python tests/browser/multiplayer.py
```

Модульные и интеграционные сценарии проверяют реальные WebSocket-соединения, сторону второго игрока, ресурсы и принадлежность, общий бой, лимиты, обрыв связи, восстановление и повторные команды. Браузерный сценарий проверяет два независимых профиля, клики строительства, сетевые меню, возврат после перезагрузки и сохранность исходных одиночных кампаний. Результаты конкретного ночного прогона записываются в `docs/qa/NIGHT-AUDIT-2026-10-22.md`.

Для публичного релиза остаются отдельные работы: постоянное хранение матчей, защищённый хостинг WSS, проверка на нестабильном интернете и разных компьютерах, подбор соперников, правила выхода из незавершённого матча и интеграция платформы. Протокол имеет версию; совместимость разных игровых сборок пока не гарантируется.

Технический ориентир: официальные [параметры ws](https://github.com/websockets/ws/blob/master/doc/ws.md) и [heartbeat](https://github.com/websockets/ws#how-to-detect-and-close-broken-connections).
