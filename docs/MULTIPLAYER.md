# Сетевая игра · интернет и локальная сеть

Комната бывает двух видов. «Дуэль»: два игрока строят города с нуля на общей карте, стартовые ресурсы и доходы равны, бота нет. «Общий фронт» (2 + бот): оба игрока командуют одной стороной с общей базой, ресурсами и армией против бота; сложность задаёт создатель комнаты. Место игрока и сторона в команде различаются (`seat` и `side` в сообщении `joined`). Сервер рассчитывает экономику, строительство, движение, попадания и победу; игроки отправляют команды. Одиночная кампания в браузере сохраняется отдельно и возвращается после выхода из сетевой сессии.

## Через интернет из разных сетей

1. Одному игроку — хозяину — нужен Node.js 24+. Он открывает `Играть через интернет.cmd`. При первом запуске скрипт устанавливает зависимости. Сначала используется системный OpenSSH и localhost.run; если этот способ недоступен, автоматически пробуется официальный `cloudflared` с проверкой загруженного файла. Другу ничего устанавливать не нужно.
2. Оставьте окно запущенным. После проверки публичного соединения у хозяина откроется локальный адрес `http://127.0.0.1:ПОРТ/?multiplayer=1`: это уменьшает задержку. Если вкладка не открылась, используйте адрес хозяина из окна сервера. Друг подключается по публичному HTTPS-приглашению.
3. Укажите имя и создайте «Дуэль» либо «Общий фронт» (2 + бот). В комнате нажмите «Копировать приглашение» и отправьте ссылку другу.
4. Друг открывает ссылку в Chrome или Edge. Сервер и код уже заполнены; остаётся имя и кнопка «Войти». Открытие ссылки само по себе не занимает место, не ставит готовность и не запускает бой.
5. Оба нажимают «Я готов», хозяин — «Начать матч». При завершении игры закройте сервер или нажмите Ctrl+C в его окне.

После установки npm-зависимостей тот же запуск доступен из терминала:

```sh
npm run multiplayer:internet
# Без автоматического открытия вкладки:
node server/index.mjs --internet --no-open
```

Сервер остаётся на loopback-адресе компьютера хозяина; туннель передаёт к нему HTTPS/WSS-трафик. Основной транспорт — системный OpenSSH через [localhost.run](https://localhost.run/docs/), резервный — Cloudflare Quick Tunnel. Аккаунт, личные SSH-ключи, настройка роутера и проброс портов не требуются. SSH использует отдельный файл известных хостов проекта. Для резервного транспорта бинарный файл фиксированной версии загружается из официального GitHub Cloudflare, проверяется по SHA-256 и хранится в игнорируемой `.tools/cloudflared/`. При первом запуске нужен доступ к npm, для резервной загрузки — к GitHub; во время партии — к выбранному туннельному сервису.

Адрес временный и перестаёт работать при остановке туннеля; бесплатный домен localhost.run может смениться и во время долгой сессии. Не закрывайте окно. Если старая ссылка перестала открываться, снова нажмите «Копировать приглашение» и отправьте новую: перед копированием игра запрашивает актуальный публичный адрес сервера. После перезапуска также понадобится новое приглашение. Это вариант для временных дружеских партий: [localhost.run ограничивает скорость и срок жизни бесплатных доменов](https://localhost.run/docs/forever-free/), а [Quick Tunnels предназначены для тестирования и не имеют гарантии доступности](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/). Ссылку сможет открыть любой, кому вы её передадите; постоянного аккаунта и поиска соперников в игре нет.

Если загрузка или запуск туннеля не удались, окно покажет причину. Проверьте доступ к интернету и повторите запуск. Для устройств в одной сети остаётся обычный локальный сервер ниже. Остановка туннеля закрывает интернет-сервер и его комнаты; незавершённая сетевая партия не становится одиночным сохранением.

## Приглашение и адрес сервера

Локальная вкладка хозяина получает публичный адрес через `/api/server-info`; кнопка приглашения отправляет другу именно публичную страницу. Локальный loopback-адрес другу передавать не нужно. До выдачи приглашения запуск проверяет JSON сервера и полный ответ размером 32 КБ, требуя три успешных проверки. Исходящие проверки учитывают `HTTPS_PROXY`/`ALL_PROXY`, исключения `NO_PROXY` и настройки прокси Windows без изменения глобальных настроек системы.

Интернет-сервер отдаёт собранный HTML без встроенных шрифтов, с кешированным gzip; шрифты загружаются отдельными файлами с `font-display: swap`. До готовности приложения виден экран загрузки. Автономный `play/Skyfront.html` по-прежнему содержит все шрифты. Для интернет-WSS включено стандартное согласуемое `perMessageDeflate` (`level: 1`, `memLevel: 7`, `concurrencyLimit: 2`); у обычного LAN-сервера сжатие по умолчанию выключено. Версия протокола остаётся 6.

Обычная ссылка комнаты — `https://АДРЕС-ИГРЫ/?room=ABC234`. Если интерфейс и игровой сервер размещены раздельно, добавляется `server` с адресом выбранного сервера. При открытии HTTPS-игры соединение использует WSS; незащищённый `ws://` в таком приглашении отклоняется до подключения.

При запуске хозяином с локального адреса `/api/server-info` выбранного игрового сервера сообщает `publicUrl`. Он используется для приглашения, а действующее локальное соединение не меняется. Автономный файл и локальный интерфейс с выбранным внешним сервером создают ссылку на HTTP(S)-страницу сервера. Сохранённый адрес прошлой комнаты не должен перекрывать адрес из нового приглашения.

В ссылку не включаются пароль, ключ восстановления места, старые query-параметры и fragment страницы. Код проверяется по формату сервера; повторные `room`/`server`, неподдерживаемые схемы и адреса со встроенными учётными данными отклоняются. Форма открывается только после завершения инициализации приложения, поэтому обычная загрузка страницы без приглашения не меняет локальную кампанию.

Для интернет-запуска существующий HTTP(S)-прокси из окружения или настроек Windows используется также для SSH методом CONNECT. Без подходящего прокси SSH подключается напрямую. Системные настройки не меняются, личный SSH-agent не используется, адрес и учётные данные прокси не выводятся. Доступность зависит от разрешения CONNECT к SSH-порту сервиса.

## Запуск на одном компьютере

1. Для сервера нужен Node.js 24 или новее. Откройте `Сетевой сервер.cmd`; при первом запуске он установит зависимости из lock-файла. Через терминал можно выполнить `npm ci`, затем `npm run multiplayer`.
2. Оставьте окно сервера открытым. По умолчанию адрес — `http://127.0.0.1:8788`.
3. Откройте этот адрес в двух браузерах или независимых профилях. На начальном экране нажмите «Сетевая дуэль».
4. Первый игрок создаёт комнату, второй вводит её шестизначный код. Оба нажимают «Я готов», создатель — «Начать матч».
5. Во время матча меню комнаты доступно через настройки. «Завершить сессию» закрывает комнату обоим игрокам и возвращает их одиночные кампании.

Клиентом может служить и автономный `play/Skyfront.html`: укажите в его сетевом меню адрес работающего сервера. Сервер и клиент должны быть из одной версии проекта.

## Второй компьютер в локальной сети

Запустите сервер с разрешением слушать сетевые интерфейсы:

```sh
npm run multiplayer -- --host=0.0.0.0
```

На другом компьютере откройте `http://IP-КОМПЬЮТЕРА-СЕРВЕРА:8788`. Устройства должны находиться в одной доступной локальной сети; если Windows запросит доступ для Node.js, разрешите его для используемой частной сети. Не требуется менять правила брандмауэра заранее.

Сервер по умолчанию слушает только этот компьютер. `--host=0.0.0.0` предназначен для доверенной локальной сети; для игры через интернет используйте отдельный запуск выше. Steam Networking и автоматического поиска игроков нет.

## Обрыв связи и возврат

Если клиент не получает сообщений 15 секунд, проверка молчащего соединения разрывает его и запускает обычный возврат. При активном цикле событий это происходит примерно через 15–18 секунд; фоновые ограничения браузера могут задержать проверку. При окончательном отказе сервера восстановить удалённую комнату сохранённые данные возврата очищаются. Это покрывает и потерю последнего сообщения о закрытии комнаты.

При потере соединения одного игрока сервер останавливает симуляцию всей комнаты. Клиент пробует восстановить подключение и своё место; накопленные ресурсы и приказы остаются на сервере. После перезагрузки страницы откройте сетевое меню и нажмите «Вернуться в прошлую комнату». Для этого в `sessionStorage` текущей вкладки хранится случайный ключ места; он не попадает в одиночное сохранение или общие снимки матча.

Матч продолжается при скрытии вкладки, пока оба подключения живы. Кнопка одиночной паузы в сетевом матче отключена. После отключения обоих игроков комната хранится ещё 15 минут. Остановка процесса сервера удаляет комнаты: постоянное сохранение сетевых партий пока отсутствует.

## Где находится код

| Часть                                                       | Файл                                                                      |
| ----------------------------------------------------------- | ------------------------------------------------------------------------- |
| Запуск и адрес сервера                                      | `server/index.mjs`                                                        |
| SSH-туннель, резервная загрузка Cloudflare и жизненный цикл | `server/ssh-tunnel.mjs`, `server/tunnel.mjs`, `Играть через интернет.cmd` |
| Комнаты, места, готовность, тик и восстановление            | `server/rooms.mjs`                                                        |
| Разрешённые команды и проверка принадлежности               | `src/network/commands.js`                                                 |
| Данные, доступные конкретному игроку, и перестановка сторон | `src/network/perspective.js`                                              |
| WebSocket-клиент, ответы на команды и интерполяция          | `src/network/client.js`                                                   |
| Проверка и сборка URL комнаты, выбор схемы и origin         | `src/network/invite.js`                                                   |
| Меню комнаты                                                | `src/ui/multiplayer.js`, `multiplayer.css`                                |
| Открытие формы по приглашению после boot                    | `src/ui/session/multiplayer-entry.js`                                     |
| Передача команд и защита от позднего ответа старой сессии   | `src/ui/session/command-executor.js`, связка в `app.js`                   |

Симуляция работает с шагом 50 мс, снимки отправляются каждые 100 мс. Клиент сглаживает движение между последними снимками, не рассчитывая исход боя самостоятельно. Идентификаторы и координаты объектов общие; для интерфейса собственная сторона всегда имеет номер 0.

Сервер принимает только разрешённые команды с проверенными аргументами. Сторону определяет закреплённое место соединения. Поддельные ресурсы, импорт состояния, чужие приказы, повторные номера команд, неизвестные виды вооружения и некорректные координаты не принимаются. Номер подтверждённой команды сохраняется при восстановлении места. Размер входящего сообщения ограничен 16 КиБ, частота — 40 сообщений в секунду; медленное соединение закрывается вместо бесконечного накопления снимков.

В 8.6 используется протокол 6, формат состояния — 12. Сохраняется контракт кооператива: сообщение `create` принимает `mode` (`pvp` или `coop`) и `difficulty`, комната сообщает их в `room`, а `joined` содержит отдельный номер места `seat`. В кооперативе оба места управляют одной стороной и её общей экономикой против бота. Команды `set-stance` и `rear-auto` сохраняют проверки принадлежности. Клиент с явно указанным старым протоколом не создаёт комнату и не входит в неё. Обновляйте сервер и оба клиента вместе.

Команда `deploy` оплачивает партию с индивидуальным местом назначения, а приказы полного отряда переназначают его ещё готовящееся пополнение. `district`, `district-repair`, `route-add`, `deliver`, `factory-plan` также проходят через шлюз принадлежности и аргументов. Районы общие, а планы заводов, будущие пути и состав очередей войск доступны лишь своей стороне.

Нефть и суда (8.6) не требуют новых команд: вышки, баки и порт строятся обычной командой `build`. Запас нефти противника скрыт, как его деньги. Чужие суда видны на воде: передаются ID, сторона, порт, положение, курс, состояние и путь; груз и торговые решения остаются приватными. Пожары хранилищ (`fire`) публичны вместе со зданием. В событиях попаданий у чужой стороны удалены `fromX/fromZ`.

Новая команда `service-enabled` принимает ID своей ремонтной станции и boolean `enabled`; чужой станцией управлять нельзя. Движение бригад и оплата реального ремонта происходят на сервере. Положения гражданских ремонтных машин публичны, как дороги и здания. Чужому клиенту передаются только их ID, сторона, положение, поворот, текущее состояние и ID станции; цель, будущий путь, дорожный кэш и расписание остаются приватными. В кооперативе партнёры имеют общую сторону и видят её рабочие данные.

Команда `auto-defense` принимает список ID своих бойцов и boolean `enabled`. Только разрешённый игроком резерв участвует в ограниченной помощи соседним секторам; исходный пост и задание переброски противника остаются приватными. Видимые чужие укрепления передают положение и стадию строительства, скрытые позиции отсекаются. Чужая память наблюдений не передаётся, а отчёт и линия фронта строятся из разрешённых стороне данных. Партнёры в кооперативе видят общие данные своей стороны.

Для видимых снарядов клиент интерполирует высоту по баллистике: `originY`, `gravity` и вертикальной скорости, а навесные артиллерийские дуги — по `arc` и времени полёта. Это сглаживает уже рассчитанный сервером полёт, не даёт клиенту определять попадания или урон и не раскрывает будущие приказы скрытого противника.

Скрытые солдаты и точные приказы противника не передаются чужому клиенту. Карта и городские объекты открыты по правилам игры; маскировка пехоты сохраняется.

## Проверки

```sh
node --test tests/unit/network-commands.test.mjs tests/unit/network-server.test.mjs tests/unit/network-client.test.mjs
node --test tests/unit/network-invite.test.mjs tests/unit/network-defense.test.mjs tests/unit/internet-tunnel.test.mjs
python tests/browser/multiplayer.py
```

Модульные и интеграционные сценарии проверяют реальные WebSocket-соединения, сторону второго игрока, ресурсы и принадлежность, общий бой, лимиты, обрыв связи, восстановление и повторные команды. Приглашение проходит полный локальный цикл: создание комнаты, сборка ссылки, разбор, вход второго соединения без автоматической готовности. Отдельные проверки покрывают проверку бинарного файла и жизненный цикл туннеля. Браузерный сценарий проверяет два независимых профиля, клики строительства, сетевые меню, возврат после перезагрузки и сохранность исходных одиночных кампаний.

Полный браузерный сценарий через публичный localhost.run прошёл: хозяин использовал локальную вкладку, гость — публичное HTTPS-приглашение. Проверены вход, готовность и старт, разные перспективы сторон, строительство и запрет чужих команд, заморозка при обрыве, автоматический и явный возврат после перезагрузки, сохранение последовательности команд и исходных одиночных кампаний. При намеренной потере последнего сообщения о закрытии проверка молчащего соединения также вернула обоих игроков в одиночную игру. Ошибок JavaScript не зарегистрировано. [Подробный итог QA 8.6 и ограничения](qa/COMMAND-86.md).

Ранние публичные загрузки обрывались во внешнем транспортном маршруте; финальная проверка прошла с новым SSH-туннелем и условным использованием настроенного прокси. Конкретная первопричина ранних обрывов не установлена. Cloudflare в текущем окружении давал кратковременные успешные ответы, затем ошибки доступности и таймауты: регистрация туннеля сама по себе не подтверждает стабильную партию.

Временный туннель не заменяет постоянный игровой сервис. Для такого сервиса остаются постоянное хранение матчей, стабильный адрес и хостинг, проверка на нестабильном интернете и разных компьютерах, подбор соперников и интеграция платформы. Протокол имеет версию; совместимость разных игровых сборок не гарантируется. Наличие локальных тестов не является гарантией доступности туннельного сервиса или качества конкретного интернет-соединения.

Технический ориентир: официальные [параметры ws](https://github.com/websockets/ws/blob/master/doc/ws.md) и [heartbeat](https://github.com/websockets/ws#how-to-detect-and-close-broken-connections).
