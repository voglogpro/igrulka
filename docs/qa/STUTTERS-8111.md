# Периодические задержки: 8.11.1

Причина запроса — короткие зависания в **одиночной 8.11.0**, а не разрыв сети. Состояние19, протокол11, сохранения, ресурсы, численность и боевые характеристики не менялись. Старые готовые выпуски и запущенные пользовательские серверы не изменялись.

Уточнение пользователя: задержки заметны при действиях, кликах и выборе места на миникарте. Для них добавлены отдельные проверки, а не только нагрузка неподвижной армией.

## Что исправлено

- Охрана ранжирует геометрически подходящие угрозы и проверяет видимость до первого подходящего противника. Дистанции, исходный порядок и ID при равенстве сохранены. Пространственный индекс зданий/окопов не позволяет каждой проверке просматривать весь город. На малых массивах и длинных лучах остаётся обычный проход.
- Оборона собирает занятые транспорты один раз; завершённое укрепление не вычисляет уровни повторно. Поиск путей, помощь соседям, платное снабжение и ручные приказы сохраняют прежние правила.
- Пехота использует Set для выделения, загружает только заполненную часть instance buffers и вычисляет общие границы при выборе мышью. Буферы растут без прежнего визуального обрезания512 бойцов одной роли или600 колец. Геометрия, материалы и внешность сохранены.
- Матрицы неподвижного ландшафта подготовлены один раз; солнце, цель света, солнечный диск и добавленные позже подвижные объекты остаются динамическими. Скрытые городские модели пересчитываются при стройке, обрушении, новых обломках и изменении размещения.
- Нажатие миникарты переносит камеру сразу с сохранением масштаба и ракурса. Прежде плавный перелёт заставлял заново рисовать тень через каждые24м промежуточного пути. Обычное движение/поворот камеры сохранены, качество и интервал теней не уменьшены.
- Существующие графические программы мира, пехоты и эффектов подготавливаются на запуске в своих render targets. Ожидание ограничено3с, отказ/потеря контекста не блокирует заставку, цель рендера восстанавливается до ожидания. Нативную компиляцию драйвера отменить через API нельзя; новые, ещё не существующие варианты материалов всё ещё могут потребовать компиляции позже.
- Каталог армии строит отчёт один раз за обновление, большие выделения и пассажиры обрабатываются через Set. Периодические панели и миникарта обновляются по одной за кадр, читают актуальное состояние и не создают очередь повторной работы. Смена кампании/сессии очищает очередь; результат боя показывается сразу.
- Закрытые подробности карточки не читают/не записывают scrollTop, что вызывало принудительную раскладку после других DOM-изменений. Изолированная Chrome DOM-проба100 обновлений:100→1 принудительных layout,164,1→3,79мс суммарной работы раскладки. Открытая карточка сохраняет прокрутку.

## Изолированные сравнения

Замеры выполнялись на занятом ноутбуке, тестовые процессы BelowNormal. Это длительности конкретной работы CPU, **не обещание игрового FPS или отсутствия всех задержек**.

| -------------------------------------------------- | ------: | ------: |

| Шаг,90 против90 и500 домов, тёплый p95             | 33,67мс | 22,34мс |
| Шаг,90 против90, повтор, тёплый p95                | 23,92мс | 22,84мс |

Первые три случая —600 шагов по0,05с, первый игровой1с исключён из тёплых перцентилей. Смешанный состав: стрелки, пулемётчики, ПТРК, Leopard и Shilka; count в runner означает количество **на сторону**. Обычные HP, дополнительного дохода в ходе прогона нет. Полные JSON/SHA состояний до и после совпали во всех трёх случаях, включая урон, пути, боезапас, бюджеты и RNG. В500 защитниках тёплый максимум122,97→98,32мс, число шагов свыше100мс3→0. В маленьком городе улучшение пиков неустойчиво: повтор дал максимум103,21→127,48мс; ранний замер содержал448,8мс выброс. Эти результаты не скрываются и не доказывают устранение каждого фриза.

Сравнения отрисовки — чередование baseline/current в одном Node-процессе. Отдельно проверены нулевые повторные композиции/умножения матриц неизменённой декорации за60 принудительных проходов, настоящее ray picking после движения, камера/тень, очистка деревьев и5000 видимых бойцов без обрезания. DOM-проба не включает браузерную раскладку.

## Настоящие клики и ограничения

Два последовательных прогона `frame_stalls.py --interactions`: AMD Radeon Vega8, ANGLE/D3D11,1280×720, прежний готовый8.11.0 и новый8.11.1. В каждом90 смешанных бойцов,12 настоящих кликов по миникарте/вкладкам/панелям, около31с наблюдения. Тест намеренно фиксирует MSAA4, тень4096 и renderScale1; штатная автоматическая адаптация отключена одинаково в обеих версиях.

Медиана интервала RAF49,7→33,6мс, p9583,2→66,9мс; обновления теней70→43. В новом мире2195 неподвижных узлов не повторяют матричную работу, подготовка шейдеров завершилась `ready`. Ошибок JavaScript нет. Самые тяжёлые JS-задачи после первых3с:128→110мс. Эти одиночные замеры на общей машине показывают уменьшение работы, но не строгую универсальную прибавку FPS.

**Полное устранение задержек каждого клика не подтверждено.** Максимум Event Timing для настоящего click остался232мс в обеих версиях, обработчики занимали примерно0,5–24мс: значительная часть задержки приходится на ожидание и представление кадра. В обеих версиях первая искусственная вставка сразу90 смешанных единиц дала около1,1с на первый GPU-кадр; подготовка уже существующих материалов на запуске не исключает новых вариантов/загрузок после массовой вставки. Эти начальные пики сохранены в сырых отчётах и не выдаются за результат обычного набора по одному бойцу. Для оставшегося конкретного подвисания требуется воспроизведение пользовательской партии, а не заявление «все фризы исправлены» по тестовой сцене.

Общий `npm run check`: **777/777 PASS**, формат, ESLint и автономная сборка. Длительный прогон12×20 минут: **240 игровых минут PASS**, обычные платные боты, без выдачи ресурсов по ходу, с сохранением/загрузкой. Пассивный человеческий штаб имеет повышенное HP, чтобы серия завершалась полностью. Логи: `check8111.log`, `soak8111.json`, `frame-stalls-8110-inputs.json`, `frame-stalls-8111-inputs.json`.

Браузерные сценарии **4/4 PASS**: `smoke` проверяет автономную и HTTP-сборку и выход из подготовки графики; `camera` — настоящую миникарту без смены масштаба/ракурса, WASD, русскую раскладку и возврат фокуса; `combat` — instanced picking,80 дополнительных стрелков без новых draw calls/геометрий, МОГ, нагрев, боезапас и50 взрывов из пула; `inspector_compact` —276 карточек на трёх разрешениях с прокруткой подробностей и без ошибок. Все используют изолированные профили. Журнал `browser8111.log`.

## Воспроизведение

```powershell
node tests/soak/frame-cost.mjs --baseline-root=C:/path/to/8.11.0 --count=90 --seconds=30 --scenario=battle --buildings=500
node tests/soak/frame-cost.mjs --baseline-root=C:/path/to/8.11.0 --count=500 --seconds=30 --scenario=defend
python tests/browser/frame_stalls.py --units=90 --seconds=30 --hardware-gpu --label=current
python tests/browser/frame_stalls.py --units=90 --seconds=20 --hardware-gpu --interactions --label=clicks
```

`frame-cost.mjs` запускает разные версии в отдельных процессах, сравнивает SHA состояния и сохраняет холодный первый шаг, тёплые перцентили и худшие тики. Не используйте CPU-медиану0 на Windows как отсутствие работы: системный счётчик грубо квантуется. `--endurance` явно повышает HP в20раз только в нагрузочной фикстуре.

Браузерный runner использует изолированный профиль,1280×720, фиксированные MSAA4/pixel ratio1/тень4096, смешанный бой с HP10000 для длительной нагрузки. Он записывает естественные кадры, длинные JS-задачи и этапы расчёта/отрисовки; временных порогов PASS для произвольного железа нет. `--hardware-gpu` требует установленный Windows Chrome; без него используется диагностический SwiftShader. Повышенные HP и отключённые боты — условия замера, не новый баланс игры. Чужая вкладка и сохранение не затрагиваются.

Локальные отчёты и профили сохраняются в игнорируемой `artifacts/qa/`: `frame-cost-*.json`, `infantry-compare811-500.json`, `building-matrix-compare811-200.json`, `recruitment-profile811-*.json`, `freeze-battle811*-90.json` и соответствующие CPU profiles.
