# Сеть и компактные карточки · 8.10.2

## Исправление загрузки и туннеля 8.10.3

После пользовательской проверки друг оставался на начальной заставке. В журнале подтверждён обрыв SSH, после которого прежний обработчик завершал весь сервер. Исправлено разделение жизненного цикла: локальный HTTP, комнаты и токены не принадлежат туннелю, запуск повторяется с задержкой 1–15 секунд. Подключение ограничено 20 секундами на попытку. Готовность CDN-режима проверяет полный ответ 2 КБ и учитывает ещё не опубликованный адрес; исправлено взаимное ожидание, при котором проверка требовала `publicUrl` до завершения той же проверки.

Сам клиент опубликован на `https://voglogpro.github.io/igrulka/` через workflow, в артефакте только самостоятельный HTML. Первичная CDN-публикация проверена со строгим TLS: HTTP 200, первый байт 764 мс, полный ответ 1,45 с, версия 8.10.2. Приглашение новой версии загружает клиент с CDN, а WSS выбирает из отдельного параметра `server`. Открытое меню хозяина опрашивает метаданные и обновляет ссылку после восстановления; LAN сохраняет локальный режим. Восстановление существующего места по новой ссылке использует обновлённый сервер только для совпадающего кода комнаты.

Ранний встроенный загрузчик до основного скрипта показывает безопасное предупреждение через 30 секунд и повтор загрузки. Проверены оборванный HTML без основного скрипта, ошибка/отклонённый Promise без раскрытия стека и URL, завершение наблюдателя после запуска, режим file://. Проверки жизненного цикла используют настоящий локальный HTTP и двух WebSocket-клиентов: запуск кооператива, потеря имитированного туннеля, тот же порт, объект комнаты, состояние и токены после повторного запуска. Строгий TLS сохранён.

Ранее описанные ограничения предельной нагрузки и бесплатного реле остаются применимы. Закрытие самого процесса по-прежнему удаляет комнаты; автоматическое восстановление не является дисковым сохранением.

Реальный браузерный CDN-прогон прошёл: хозяин на localhost новой версии создал приглашение на GitHub Pages с явным WSS, гость открыл именно эту ссылку. Первый байт 937 мс, загрузка HTML 569 мс, полная готовность приложения с холодным 3D в программном QA-браузере 16,219 с. Затем оба вошли и подтвердили готовность, запустили четыре города со сторонами 0/2, купили дороги и увидели обе дороги в обоих клиентах. Ошибок JavaScript нет, закрыта только тестовая комната. На момент проверки CDN содержал совместимую 8.10.2; следующий push обновляет самостоятельный клиент до 8.10.3. Отчёт — `artifacts/qa/cdn-invite-report.json`. Предыдущий заблокированный запуск сохранён отдельно и не засчитан: он помог выявить взаимное ожидание проверки готовности.

Итоговая проверка 8.10.3: `npm run check` — **693/693 PASS**, Prettier, ESLint, автономная сборка без внешних ресурсов. HTML — 3 039 064 байта, SHA-256 `aadd99f4d7fc59e83eaaedaa20b0ed200e6518814e69aee370c12e225f27c6b3`. Одна промежуточная проверка холодного CLI превысила пятисекундный тестовый предел при параллельных работниках; ожидание расширено до 15 секунд с немедленным отказом при выходе дочернего процесса, проверка фактического слушателя и его закрытия сохранена.

Пользователь сообщил о задержках и остановке кооператива после появления вражеских дронов. Первая версия отправляла полное состояние обоим игрокам каждые 100 мс, копировала весь авторитетный мир до удаления приватных данных и закрывала соединение после накопления 2 МБ исходящих сообщений. Движение также повторно синхронизировало весь 3D-мир при каждом сетевом ответе. Эти источники нагрузки исправлены; прежняя пользовательская партия не инструментировалась, поэтому конкретный внешний сбой туннеля задним числом не установлен.

## Что изменено

- Дополнительный формат `delta-v1`: полный мир при входе/возврате, затем изменения по ID; словарь полей, добавления/удаления, новые события. Пройденные головы маршрутов и добавленные точки передаются отдельно от оставшегося пути. Номера снимков монотонны, потеря базы вызывает полный `resync`.
- Один неподтверждённый снимок на игрока и один ленивый запрос на свежий мир. Пока клиент не обработал предыдущий мир, устаревшие состояния не сериализуются. Командные ответы, room и pong обслуживаются независимо; очередь управления ограничена.
- Интервал 100–500 мс по фактическому RTT и времени подготовки данных. Расчёт боя и урон остаются серверными; ожидание снимка не выдаётся за отключение. Реальная потеря игрока по-прежнему останавливает общую партию.
- Сначала фильтрация разрешённых данных, затем копирование. Полные проекции остаются отделёнными; заимствованная проекция допустима только для немедленного синхронного кодирования. Чужие приказы, склады и скрытая пехота не раскрываются.
- Координаты отображения округляются до сантиметра; бюджет, HP, расходы и симуляция не округляются. Повторные сетевые проходы `world.sync` убраны, индексы интерполяции кешируются вне неизменяемых образцов.
- Карточки зданий и армии показывают улучшение, ремонт и основные действия сразу. Подробности по умолчанию закрыты, раскрытие не сдвигает команды. Состояние раскрытия, фокус и существующая кнопка сохраняются при обновлении и замене сетевого состояния.

Формат сохранений 17 и базовый протокол 10 сохранены. Клиент без согласования дополнительного кодирования получает прежний полный формат. Для ускорения нужно создать комнату на новом сервере и обоим открыть обновлённую страницу.

## Нагрузка

Воспроизводимые сценарии: `tests/support/network-load.mjs`, `tests/soak/network.mjs`, `tests/soak/network-load.mjs`. Четыре города, 120 наземных единиц на город, настоящие перемещения, огонь ПВО, снаряды и обычное здоровье дронов. Ранние варианты fixture с дополнительными очередями поверх лимита и без фактической стрельбы ПВО не использованы как итог.

Сравнение кодирования после прогрева, 3 игровые секунды, 20 шагов/с и 10 снимков/с двум людям. Числа — сумма двух потоков, сжатие deflate level 1 каждого сообщения отдельно:

Все восстановленные бюджеты и HP совпали с сервером точно; периодически весь результат сверялся с новым полным нормализованным снимком. Время 3 секунды здесь означает продолжительность сравнительного профиля, а не длительность отдельной игры.

В каждом прогоне стороны 0/2, четыре штаба, активная партия, реальные воздушные снаряды ПВО, очередь будущих снимков не больше одного, исходящий TCP-буфер не нарастал. Это тест задержанного подтверждения, а не измерение пропускной способности произвольного домашнего канала. Обе тестовые клиентские обработки и сервер находятся в одном Node-процессе. Даже здесь предельная армия не дала стабильных 20 шагов/с; универсальная плавность на слабом ноутбуке и неограниченное количество войск не заявляются. Сохраняется существующий лимит 120 наземных и 120 воздушных единиц на город.

## Интерфейс и браузер

Проверены 276 сочетаний карточек и уровней на 1024×768, 1366×768 и 1024×600. Основные карточки не прокручиваются, действия находятся в пределах экрана; открытые характеристики на стандартной высоте 768 также помещаются. В настоящем автономном HUD выполнены оплаченные улучшения здания и МОГ, проверены ремонтная служба, казарма и производство. Ошибок JavaScript нет. На высоте 600 длинные дополнительные сведения могут прокручиваться отдельно, не затрагивая основные действия.

Два изолированных браузера прошли полный локальный кооператив с дополнительным кодированием: приглашение, четыре города, строительство кликами на карте, запрет союзного сноса, обрыв и автоматический возврат, перезагрузка гостя и восстановление места/номеров команд, возвращение обеих одиночных кампаний. `smoke` прошёл для автономного HTML без сетевых запросов и модулей по HTTP.

Следующим отдельным обновлением согласована переделка поселений с готовым подъездом и обычными экономическими зданиями; в 8.10.2 эта механика не заявлена.

Итоговый `npm run check` прошёл: **681/681**, Prettier, ESLint и сборка без внешних ресурсов. Первые две неудачные проверки сохранены в исходном отчёте: кеш индексов теперь находится вне неизменяемых образцов, DOM-мок расширен настоящим контрактом `contains`/дочерних узлов без ослабления запретов управления союзником. Итоговый HTML — 3 036 147 байт, SHA-256 `bb7a15963739da2a77c3b0b4fd6d2ef4c157df79970725b07877473acd35919d`.

Публичный интернет-прогон также прошёл со строгим TLS: сначала полный HTTPS HTML, затем отдельная партия localhost-хозяина с гостем через публичный WSS. Получено 694 887 байт gzip при том же Content-Length, контроль распаковки и версия подтверждены; загрузка заняла 61,4 с. В своей комнате четыре штаба и стороны 0/2, оба игрока купили дорогу за 32 денег, применено `delta-v1`, ответы на команды не содержат полное состояние, в полёте не больше одного неподтверждённого снимка.
